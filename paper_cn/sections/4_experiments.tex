\section{实验}\label{sec:experiments}

\subsection{数据集与评价协议}\label{sec:data}
\paragraph{AgriOcc-Dataset。}
本文基于 UE5 FarmSim 数据建立农业语义占用训练协议。每一帧含六路 RGB、传感器内外参、机器人位姿、原始占用标签与有效掩码；主实验仅使用前三路相机。原始标签经过固定映射合并为六个类别：free、crop、soil\_ground、drivable、other\_vegetation 和 other\_obstacle。训练/验证划分分别含 248/50 个互不重叠的序列、32,385/6,477 帧。占用文件按 $[z,y,x]$ 存储，加载时转换为模型使用的 $[x,y,z]$；无效和未映射标签均置为 ignore。由于主任务使用当前图像，\texttt{history-frames}=0，且不预测未来占用和规划轨迹。

\paragraph{ORAD-3D。}
为测试仿真到真实越野环境的迁移，使用 ORAD-3D 的单目当前帧占用任务\cite{chen2025orad3d}。与 RELLIS-3D 等越野多模态数据\cite{jiang2020rellis}相比，ORAD-3D 直接提供本文所需的体素占用评价接口。其输出为 $100\times100\times16$ 九类体素（free、road、safe-road、car、people、water、snow、grass-on-road、rock），坐标轴由原始 right/forward/up 转换为本文的 forward/right/up。FarmSim 与 ORAD-3D 的类别和相机数不同，因而先将 FarmSim checkpoint 中形状兼容的张量加载到 ORAD 模型；三相机 embedding 取中心前视 embedding，新的单目 embedding 和九类占用头由固定随机种子初始化，再对 ORAD 训练集的不同数据比例微调。

\paragraph{指标。}
对类别 $c$，$\IoU_c=\mathrm{TP}_c/(\mathrm{TP}_c+\mathrm{FP}_c+\mathrm{FN}_c)$；mIoU 为有效类别 IoU 的算术均值。FarmSim 的六类均出现在验证集，故报告六类 mIoU、每类 IoU 与体素准确率。ORAD-3D 仅在包含五个测试序列的 \texttt{test\_farm} 子集上重新评估；表\ref{tab:orad}中的 mIoU 使用评估器导出的 \texttt{semantic\_mIoU}。参数量取训练日志中构建模型的可训练参数数目。

\subsection{实现细节}\label{sec:implementation}
所有 FarmSim 主实验采用 ResNet-101、四级 FPN、6 层 BEV encoder 与 3 层 occupancy decoder。输入尺寸为 $512\times288$；体素范围为 $[0,20]\times[-10,10]\times[-2,3]$ m，分辨率 $0.2$ m。优化器为 AdamW，初始学习率 $2\times10^{-4}$，权重衰减 0.01，余弦学习率策略，500 iteration 线性 warm-up。使用 4 张 RTX 4090、每卡 batch size 3、有效全局 batch size 24 和 FP16 训练 8 epoch。图像编码器加载 \texttt{r101\_dcn\_fcos3d\_pretrain.pth}；配置中冻结 ResNet 第 1 stage，并将 BN 设为 eval/不更新仿射参数。所有已填 FarmSim 结果均来自固定 seed 0 的单次运行。

完整 AgriOcc 使用 8 个注意力头、$4\times8$ 可见锚点；Agri-AMoE 的三维通道数为 96，启用通道/空间显著性和梯度能量路由，路由温度为 1；近远场近区比例为 0.6、远场步长为 2。ORAD-3D 微调保持 $512\times288$ 图像尺寸与有效全局 batch size 24；不同数据比例的训练轮数如表\ref{tab:orad}所示。

\subsection{体素分辨率迁移}\label{sec:resolution_transfer}
农业机器人在垄间通行、株间避障和精细作业时，$0.2\times0.2\times0.2\,$m 的体素可能将相邻作物、窄垄沟或局部可通行边界量化到同一网格中。将整个 BEV 编码器直接扩展到 $0.1\times0.1\times0.2\,$m 会使 XY 查询数从 $100\times100$ 增至 $200\times200$，即增加四倍；相应地，多尺度图像--BEV 交互、BEV 中间激活和三维占用监督的计算与显存开销均显著上升。为此，本文进一步验证 AgriOcc 是否能够将已学习的粗分辨率三维先验高效迁移到细分辨率占用预测。

具体地，迁移模型首先在 $0.2\times0.2\times0.2\,$m FarmSim 数据上完成训练，保留其 $100\times100$ GVAD--Agri-AMoE--NearFar BEV 编码器；随后在 $0.1\times0.1\times0.2\,$m 数据上微调，并在占用输出端加入学习式 $2\times$ 细化头。该头将粗占用 logits 与相应的 BEV 特征投影融合，输出 $200\times200\times25$ 体素。对照组采用相同的 0.1 m 训练/验证划分、图像输入和 4 epoch 训练时长，但从公开二维图像预训练初始化，直接学习 $200\times200$ 的高分辨率 BEV 与占用预测。两组结果如表\ref{tab:resolution_transfer}所示。

分辨率迁移将 mIoU 从 36.18\% 提升至 49.01\%，绝对提高 12.83 个百分点；六类 IoU 均有提升，其中 soil\_ground 和 drivable 分别提高 20.83 和 24.18 个百分点。该结果表明，$0.2\,$m 预训练并未只学习粗糙的类别模板，而是已在图像到 BEV 的投影、可见性约束和场景级语义布局中建立了可复用的三维表征。微调阶段无需从有限的高分辨率数据中重新估计相机几何和大范围田间结构，而是将学习能力集中于细网格上的局部边界、垄沟与作物间隙恢复。

从优化角度看，直接高分辨率训练必须同时学习四倍数量的 BEV 查询及其图像对应关系；在训练样本规模不变时，每个高分辨率体素获得的有效几何观测更稀疏，细粒度 crop--free 边界还受到显著类别不平衡的影响。迁移方案保留 $100\times100$ 编码器的稳定全局上下文，并以残差式 $2\times$ 输出细化将粗预测上采样到 0.1 m 网格。因而，细化头只需学习粗网格未表达的高频空间残差，而不必重建完整的三维场景；这解释了其在作物、地面和可通行区域上的一致增益，也说明 AgriOcc 能在不承担端到端高分辨率 BEV 编码成本的条件下适配精细农业感知需求。

\subsection{讨论}\label{sec:discussion}
AgriOcc 的总体增益集中于地面、可通行区域和复杂背景类别，说明可见性建模、三维结构自适应解码和近远场计算分配能够提升农业场景的大范围空间一致性。作物类别仍是最具挑战性的部分：相邻植株和叶片间隙在单帧三相机投影及 $0.2\,$m 体素化后易发生混合。Agri-AMoE 通过梯度能量在平面局部、垂直和大范围上下文专家之间逐体素路由；完整组合的 crop IoU 为 28.82\%，因此仍需通过多随机种子和补全累积组合消融检验其与 GVAD、NearFar 的交互。NearFar 将近场分辨率优先级显式编码到查询布局中，为农业机器人部署中的精细感知与高效计算提供了统一设计。
